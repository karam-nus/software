# Appendix A — Package Management Deep Dive

> "The best code is useless if nobody can install it." — Every ML engineer who has debugged a CUDA mismatch at 2 AM.

This appendix is your daily reference for Python package management. It covers **pip**, **conda**, and **uv** in exhaustive detail — commands, configuration files, best practices, and real-world workflows for ML projects.

---

## A.1 pip — The Standard Package Installer

pip is the default package installer for Python and the foundation of the Python packaging ecosystem.

### Basic Commands

```bash
# Install a package
pip install numpy

# Install a specific version
pip install numpy==1.26.4

# Install with version constraints
pip install "numpy>=1.24,<2.0"

# Install multiple packages
pip install numpy pandas scikit-learn

# Install from a requirements file
pip install -r requirements.txt

# Install in editable/development mode (symlinks your source)
pip install -e .

# Install with optional extras
pip install "transformers[torch,sentencepiece]"

# Upgrade a package
pip install --upgrade numpy

# Uninstall a package
pip uninstall numpy

# Show installed package info
pip show numpy

# List all installed packages
pip list

# List outdated packages
pip list --outdated
```

### requirements.txt — Pinning Dependencies

```txt
# requirements.txt — production dependencies
numpy==1.26.4
pandas==2.2.1
scikit-learn==1.4.1
torch==2.2.1
transformers==4.38.2
wandb==0.16.4
```

```txt
# requirements-dev.txt — development-only dependencies
-r requirements.txt
pytest==8.1.1
pytest-cov==4.1.0
ruff==0.3.4
mypy==1.9.0
pre-commit==3.6.2
ipython==8.22.2
```

### pip freeze — Snapshot Your Environment

```bash
# Dump ALL installed packages (including transitive dependencies)
pip freeze > requirements-lock.txt

# This captures everything — often 200+ packages for an ML project
# Not ideal for a human-maintained requirements.txt
```

> **Warning**: `pip freeze` captures everything, including packages you didn't ask for. Use `pip-compile` for a cleaner workflow.

### pip-tools — The Professional Workflow

pip-tools gives you a two-file workflow: a human-readable `.in` file and a machine-generated locked `.txt` file.

```bash
# Install pip-tools
pip install pip-tools

# Create your human-readable input file
cat > requirements.in << 'EOF'
numpy>=1.24
pandas>=2.0
torch>=2.2
transformers>=4.38
wandb
EOF

# Compile to a fully pinned requirements.txt with hashes
pip-compile requirements.in --output-file requirements.txt --generate-hashes

# Compile dev dependencies separately
pip-compile requirements-dev.in --output-file requirements-dev.txt

# Sync your environment to match the lock file exactly
pip-sync requirements.txt requirements-dev.txt

# Upgrade a single package (and its dependencies)
pip-compile --upgrade-package torch requirements.in

# Upgrade all packages
pip-compile --upgrade requirements.in
```

**Generated `requirements.txt` (by pip-compile):**
```txt
# This file is autogenerated by pip-compile with Python 3.11
# by the following command:
#     pip-compile --generate-hashes requirements.in
numpy==1.26.4 \
    --hash=sha256:a45c...
    # via
    #   -r requirements.in
    #   pandas
    #   scikit-learn
    #   transformers
pandas==2.2.1 \
    --hash=sha256:b12d...
    # via -r requirements.in
```

### Constraints Files

Constraints files pin versions without adding packages — useful for organization-wide version policies.

```bash
# constraints.txt — shared across your org
numpy==1.26.4
protobuf==4.25.3
grpcio==1.62.1

# Use constraints when installing
pip install -c constraints.txt -r requirements.txt
```

### pip Cache and Offline Installs

```bash
# Show cache info
pip cache info

# Download packages without installing (for offline use)
pip download -r requirements.txt -d ./packages/

# Install from a local directory
pip install --no-index --find-links=./packages/ -r requirements.txt

# Clear the pip cache
pip cache purge
```

### Editable Installs for Development

```bash
# Install your own package in development mode
pip install -e .

# With extras
pip install -e ".[dev,test]"

# This requires a pyproject.toml or setup.py
```

**pyproject.toml for editable installs:**
```toml
[project]
name = "my-ml-project"
version = "0.1.0"
dependencies = [
    "numpy>=1.24",
    "torch>=2.2",
    "transformers>=4.38",
]

[project.optional-dependencies]
dev = ["pytest", "ruff", "mypy"]
```

## A.2 conda — Environment and Package Manager

conda manages both Python packages and system-level binary dependencies (CUDA, MKL, etc.), making it popular in ML/scientific computing.

### Environment Management

```bash
# Create a new environment with a specific Python version
conda create -n myproject python=3.11

# Activate the environment
conda activate myproject

# Deactivate
conda deactivate

# List all environments
conda env list

# Remove an environment
conda env remove -n myproject

# Clone an environment
conda create --clone myproject -n myproject-backup
```

### Installing Packages

```bash
# Install from defaults channel
conda install numpy pandas scikit-learn

# Install from conda-forge (community channel, more packages)
conda install -c conda-forge transformers

# Install a specific version
conda install numpy=1.26.4

# Install PyTorch with CUDA (conda handles CUDA automatically!)
conda install pytorch torchvision torchaudio pytorch-cuda=12.1 -c pytorch -c nvidia

# Search for a package
conda search transformers -c conda-forge

# Update a package
conda update numpy

# Update all packages
conda update --all
```

> **Key advantage**: `conda install pytorch pytorch-cuda=12.1` handles the entire CUDA dependency chain. With pip, you must manage CUDA separately.

### environment.yml — Declarative Environments

```yaml
# environment.yml
name: ml-project
channels:
  - pytorch
  - nvidia
  - conda-forge
  - defaults
dependencies:
  - python=3.11
  - pytorch=2.2.1
  - pytorch-cuda=12.1
  - torchvision
  - numpy=1.26.4
  - pandas=2.2.1
  - scikit-learn=1.4.1
  - jupyter
  - matplotlib
  # pip packages not available on conda
  - pip:
    - transformers==4.38.2
    - wandb==0.16.4
    - einops==0.7.0
```

```bash
# Create environment from YAML
conda env create -f environment.yml

# Update environment from YAML
conda env update -f environment.yml --prune

# Export environment (exact)
conda env export > environment-lock.yml

# Export environment (portable — no build strings)
conda env export --no-builds > environment.yml
```

### Channels and Channel Priority

```bash
# Configure conda-forge as default (recommended)
conda config --add channels conda-forge
conda config --set channel_priority strict

# View config
conda config --show channels
conda config --show channel_priority
```

**~/.condarc:**
```yaml
channels:
  - pytorch
  - nvidia
  - conda-forge
  - defaults
channel_priority: strict
auto_activate_base: false
```

### conda vs pip Mixing — The Safe Way

> **Rule**: Install as much as possible with conda first, then use pip for the rest. Never `conda install` after `pip install` in the same environment.

```bash
# CORRECT order
conda create -n myproject python=3.11
conda activate myproject
conda install pytorch pytorch-cuda=12.1 -c pytorch -c nvidia  # conda first
conda install numpy pandas scikit-learn                        # conda second
pip install transformers wandb einops                          # pip last

# INCORRECT — this breaks things
conda install numpy
pip install some-package
conda install pandas        # ← this can overwrite pip packages!
```

### mamba — Drop-in Faster Conda

```bash
# Install mamba (much faster dependency solver)
conda install -n base -c conda-forge mamba

# Use exactly like conda, just replace the command
mamba create -n myproject python=3.11
mamba install -c conda-forge transformers
mamba env create -f environment.yml
```

### conda-lock — Cross-Platform Lock Files

```bash
# Install conda-lock
pip install conda-lock

# Generate lock file from environment.yml
conda-lock -f environment.yml -p linux-64 -p osx-arm64

# Install from lock file (exact reproduction)
conda-lock install conda-lock.yml
```

## A.3 uv — The Modern Python Package Manager

uv is an extremely fast Python package installer and resolver written in Rust. It is rapidly becoming the standard for new Python projects.

### Getting Started

```bash
# Install uv
curl -LsSf https://astral.sh/uv/install.sh | sh

# Or with pip
pip install uv

# Check version
uv --version
```

### Virtual Environment Management

```bash
# Create a virtual environment
uv venv

# Create with a specific Python version (auto-downloads if needed!)
uv venv --python 3.11

# Activate (same as standard venv)
source .venv/bin/activate

# Create in a custom location
uv venv myenv
```

### Installing Packages

```bash
# Install packages (10-100x faster than pip)
uv pip install numpy pandas torch

# Install from requirements.txt
uv pip install -r requirements.txt

# Install with extras
uv pip install "transformers[torch]"

# Install in editable mode
uv pip install -e ".[dev]"

# Uninstall
uv pip uninstall numpy
```

### uv pip compile — Lock Files

```bash
# Compile requirements.in → requirements.txt (locked)
uv pip compile requirements.in -o requirements.txt

# With hashes for supply chain security
uv pip compile requirements.in -o requirements.txt --generate-hashes

# For different Python version
uv pip compile requirements.in -o requirements.txt --python-version 3.11

# Upgrade all
uv pip compile requirements.in -o requirements.txt --upgrade

# Upgrade single package
uv pip compile requirements.in -o requirements.txt --upgrade-package torch
```

### uv pip sync — Exact Environment Reproduction

```bash
# Sync environment to match lock file exactly (removes extra packages)
uv pip sync requirements.txt

# Sync multiple requirement files
uv pip sync requirements.txt requirements-dev.txt
```

### uv Project Workflow (pyproject.toml native)

```bash
# Initialize a new project
uv init my-ml-project
cd my-ml-project

# Add dependencies (updates pyproject.toml + uv.lock)
uv add numpy pandas torch
uv add transformers --extra torch

# Add dev dependencies
uv add --dev pytest ruff mypy

# Remove a dependency
uv remove wandb

# Sync environment from lock file
uv sync

# Run a command in the project environment
uv run python train.py
uv run pytest

# Update the lock file
uv lock --upgrade
```

**Generated pyproject.toml:**
```toml
[project]
name = "my-ml-project"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = [
    "numpy>=1.26.4",
    "pandas>=2.2.1",
    "torch>=2.2.1",
    "transformers[torch]>=4.38.2",
]

[dependency-groups]
dev = [
    "pytest>=8.1.1",
    "ruff>=0.3.4",
    "mypy>=1.9.0",
]
```

### uv tool — Global CLI Tools

```bash
# Run a tool without installing it
uv tool run ruff check .

# Install a tool globally
uv tool install ruff
uv tool install pre-commit

# List installed tools
uv tool list

# Upgrade a tool
uv tool upgrade ruff
```

## A.4 Comparison Table — pip vs conda vs uv

| Feature | pip | conda | uv |
|---|---|---|---|
| **Speed** | Slow | Slow (mamba: fast) | ⚡ Extremely fast |
| **Language** | Python | Python/C++ | Rust |
| **Lock files** | pip-tools | conda-lock | Built-in (uv.lock) |
| **Python management** | ✗ | ✓ | ✓ |
| **CUDA/GPU support** | Manual | ✓ Automatic | Manual |
| **Non-Python deps** | ✗ | ✓ (C libs, etc.) | ✗ |
| **Resolver** | Backtracking | SAT solver | Pubgrub (fast) |
| **Editable installs** | ✓ | Limited | ✓ |
| **Hash checking** | ✓ | ✗ | ✓ |
| **Ecosystem** | PyPI (500k+) | conda-forge (25k+) | PyPI (500k+) |
| **Reproducibility** | Good (with pip-tools) | Good (with conda-lock) | Excellent (built-in) |
| **Learning curve** | Low | Medium | Low |

## A.5 Best Practices

### Pin Versions for Reproducibility

```txt
# BAD — non-deterministic
numpy
pandas
torch

# BETTER — lower bounds
numpy>=1.26
pandas>=2.2
torch>=2.2

# BEST — fully pinned in lock file
numpy==1.26.4
pandas==2.2.1
torch==2.2.1+cu121
```

### Separate Dev and Prod Dependencies

```toml
# pyproject.toml
[project]
dependencies = [
    "torch>=2.2",
    "transformers>=4.38",
    "fastapi>=0.110",
]

[dependency-groups]
dev = [
    "pytest>=8.0",
    "ruff>=0.3",
    "mypy>=1.9",
]
test = [
    "pytest>=8.0",
    "pytest-cov>=4.1",
    "httpx>=0.27",          # for testing FastAPI
]
```

### Managing CUDA and cuDNN

```bash
# Option 1: conda manages everything (simplest)
conda install pytorch pytorch-cuda=12.1 -c pytorch -c nvidia

# Option 2: pip with PyTorch's CUDA-bundled wheels
pip install torch --index-url https://download.pytorch.org/whl/cu121

# Option 3: System CUDA + pip
# First install CUDA toolkit system-wide, then:
pip install torch

# Check CUDA availability
python -c "import torch; print(torch.cuda.is_available()); print(torch.version.cuda)"
```

### PyTorch Extra Index URLs

```txt
# requirements.txt for CUDA 12.1
--extra-index-url https://download.pytorch.org/whl/cu121
torch==2.2.1
torchvision==0.17.1
torchaudio==2.2.1
```

## A.6 Common Workflows

### Setting Up a New ML Project (uv)

```bash
# 1. Create project
uv init my-ml-project && cd my-ml-project

# 2. Set Python version
uv venv --python 3.11

# 3. Add dependencies
uv add numpy pandas scikit-learn matplotlib
uv add torch --index-url https://download.pytorch.org/whl/cu121
uv add transformers datasets wandb

# 4. Add dev dependencies
uv add --dev pytest ruff mypy pre-commit ipython

# 5. Lock and sync
uv lock
uv sync

# 6. Verify
uv run python -c "import torch; print(torch.cuda.is_available())"
```

### Reproducing Someone Else's Environment

```bash
# With uv (if uv.lock exists)
uv sync

# With pip (if requirements.txt exists)
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# With conda (if environment.yml exists)
conda env create -f environment.yml
conda activate ml-project
```

### Upgrading Dependencies Safely

```bash
# 1. Create a branch
git checkout -b deps/upgrade-torch

# 2. Upgrade the specific package
uv add "torch>=2.3"      # uv updates pyproject.toml + uv.lock
# or
pip-compile --upgrade-package torch requirements.in

# 3. Run tests
uv run pytest

# 4. Commit and PR
git add -A && git commit -m "chore: upgrade torch to 2.3"
```

### Auditing for Vulnerabilities

```bash
# Using pip-audit
pip install pip-audit
pip-audit

# Using uv
# uv resolves hashes by default — check with:
uv pip compile requirements.in --generate-hashes -o requirements.txt

# Using safety
pip install safety
safety check -r requirements.txt
```
